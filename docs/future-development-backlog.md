# 后续开发计划

更新时间：2026-07-13

## P0 真实设备联调

状态（2026-07-13）：小智普通 Wi-Fi、手机热点、断网恢复、MQTT 日志和本地 AI WebSocket 对话均已完成实机验证；后端 `startup`/`firmware_started` 新批次边界、日志中文化、5 秒自动刷新、批量删除及其重复选择修复均已重启复验。本地 AI 取消/不可用后可回退官方 AI，但回退耗时偏长；本地 AI 模型能力也弱于官方。两项均已记录为延期观察，当前不处理。仍保留长时间稳定性及固件端是否重复发布启动事件的观察项。

- 确认设备使用 WiFi、网线、4G 或网关联网
- 确认使用 HTTP、MQTT 或两者兼容
- 配置部署电脑或服务器 IP
- 验证持续上报、断线重连、异常日志和趋势数据
- 记录真实设备固件版本、Topic 和 JSON 格式

学习目标：理解设备联网、IP、端口、HTTP/MQTT 客户端、心跳和断线重连。

完成标准：真实设备连续上报至少 30 分钟；断网恢复后可重新连接；正常与异常数据能正确入库、展示并生成日志。

## P1 安全

状态（2026-07-13）：全局 MQTT 凭证管理已完成实机切换：已创建凭证、关闭匿名访问、重启服务，并由小智填写相同凭证后验证上报。管理网页登录、HTTP 设备认证、TLS 和多设备独立 ACL 仍未实现。

- Spring Security + JWT 登录
- 管理员、运维、只读角色
- HTTP 设备身份认证
- MQTT 用户名、密码和 ACL
- 公网部署启用 TLS，禁止匿名 MQTT

学习目标：掌握 Spring Security、JWT、密码哈希、设备凭证、MQTT ACL 和 TLS。

完成标准：未登录用户不能访问管理接口；不同角色权限生效；无效设备凭证不能上报；匿名 MQTT 被拒绝。

## P3 工程质量

- OpenAPI/Swagger
- 后端和前端自动化测试
- Actuator 健康检查
- 统一运行日志与错误码
- 数据库升级脚本
- 按需加入 Redis 和 Nginx 生产配置

学习目标：掌握接口文档、测试分层、健康检查、数据库迁移和生产日志。

完成标准：核心服务有自动化测试；API 文档可访问；健康检查可用于容器判断；数据库升级不依赖删除数据卷。

## P4 AI 功能

- 日志智能总结
- 异常原因分析
- 维护建议
- 设备历史关联分析

学习目标：理解 Java 业务服务与 Python/AI 服务的职责边界、结构化提示和结果存储。

完成标准：AI 分析有明确输入、输出和失败处理；结果可追溯，不直接替代原始日志和规则告警。
